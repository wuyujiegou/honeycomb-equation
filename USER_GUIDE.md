# Honeycomb Equation Software User Guide

## 1. What this package is

This package is the HE reference executable semantics used to check query-scoped proof credit, support closure, query assembly, six-face conformance, lineage, PDE examples, coupling/defect examples, and weak-limit evidence ingress.

It is **not** a general PDE solver, FEM/FVM package, or a universal theorem prover.

## 2. Requirements

- Python 3.11 or newer is declared by the package.
- The evaluated runtime for the current paper artifact is CPython 3.13.5.
- `pytest` is needed only to run the full test suite.
- The core runtime has no external numerical-solver dependency.

## 3. Install and run the self-check

From the extracted package directory:

```bash
python -m venv .venv
```

Activate the environment. The simplest installation uses the bundled wheel and does not require a local build backend:

```bash
python -m pip install dist/*.whl
```

To rebuild and install from source instead:

```bash
python -m pip install .
```

Run the installed semantic conformance check:

```bash
he-selfcheck
```

A passing installation reports, among other fields:

```text
ConformancePASS=true
OracleCount=30
OraclePassCount=30
CapabilityCount=14
SemanticBaseline=HE_CORE_CLOSED_LOOP
```

## 4. Reproduce the source release gate

From the package root:

```bash
PYTHONPATH=src python run_release.py
```

The source release gate checks the pinned release identity, 30 semantic oracles, 14 mandatory capabilities, trust-policy requirements, examples, theorem fixtures, and the closed-loop guard.

Expected result: `ReleasePASS=true` and exit code 0.


## 4A. One-command package verification

After installing `pytest`, the package-level verification helper runs the release gate and full regression suite:

```bash
python -m pip install pytest
python verify_package.py
```

A successful run ends with `PACKAGE_VERIFY=PASS`. This helper does not perform the external rigorous PDE replay, which remains `OPEN`.

## 5. Run all regression tests

Install pytest if needed:

```bash
python -m pip install pytest
```

Then run:

```bash
PYTHONPATH=src python -m pytest -q
```

The evaluated baseline contains 92 tests.

## 6. Run PDE examples

### Heat equation, homogeneous Neumann boundary

```bash
PYTHONPATH=src python run_pde.py \
  examples/heat_neumann.model.json \
  --query examples/heat_mean.query.json \
  --auto-evidence
```

### Heat equation with declared open flux

```bash
PYTHONPATH=src python run_pde.py \
  examples/heat_open_port.model.json \
  --query examples/heat_open_mean.query.json \
  --auto-evidence
```

The open flux may remain in an exact law while an exact value query remains unsupported without certified port history.

### Reaction-diffusion invariant

```bash
PYTHONPATH=src python run_pde.py \
  examples/reaction_diffusion.model.json \
  --query examples/reaction_invariant.query.json \
  --auto-evidence
```

## 7. Run interface-composition examples

Exact coupling:

```bash
PYTHONPATH=src python run_pde.py \
  examples/two_cell_interface.bundle.json \
  --query examples/two_cell_global_mean.query.json \
  --auto-evidence
```

Defect-bearing coupling:

```bash
PYTHONPATH=src python run_pde.py \
  examples/two_cell_interface_defect.bundle.json \
  --query examples/two_cell_defect_global_mean.query.json \
  --auto-evidence
```

## 8. Run weak-limit evidence examples

Oscillation:

```bash
PYTHONPATH=src python run_weak_evidence.py examples/weak_oscillation.evidence.json
```

Concentration:

```bash
PYTHONPATH=src python run_weak_evidence.py examples/weak_concentration.evidence.json
```

The current verifier is deliberately narrow. These examples exercise pinned theorem-backed witness families; they do not establish arbitrary external numerical weak-limit results.

## 9. Interpreting common outcomes

- `PASS`: the corresponding certified conformance obligation is satisfied.
- `OPEN`: available certified support is insufficient for the requested stronger conclusion.
- `UNSUPPORTED`: submitted evidence does not receive the requested proof credit.
- `INVALID`: the evidence or contract fails its checker.
- `CERTIFIED_OUTER_RELATION`: a certified enclosing/generalized relation is available, but strong exactness has not been licensed.

A nonzero return code can therefore represent a **correct refusal**, not necessarily a program crash.

## 10. Verification and independence boundary

The internal HE conformance results are generated by this executable artifact. They do not depend on a successful independent machine replay of the external rigorous PDE papers discussed in the manuscript. That external replay remains `OPEN` and is not used to justify the 92-test, 30-oracle, or 14-capability internal results.

## 11. Rebuilding the release manifest

`build_release_manifest.py` is provided for controlled release reconstruction. Rebuilding the manifest after source changes creates a new source identity; it must not be used to pretend that modified source is the same frozen release.

## 12. Troubleshooting

If `run_release.py` reports `release manifest identity mismatch`, the source tree or pinned release inputs differ from the manifest. Do not edit the manifest merely to suppress the failure unless you are intentionally creating a new release.

If `he-selfcheck` is not found, confirm that the package was installed into the active Python environment.

If a PDE query exits nonzero while printing a structured `OPEN` or `UNSUPPORTED` result, inspect the returned semantic status before treating it as a software failure.
